# 增量实现（Incremental Implementation）

## 概述

增量循环：Implement → Test → Verify → Commit → 下一片。每片后保持可编译可测试。

## 何时使用

- 多文件变更
- 从 task breakdown 实现新功能
- 重构现有代码
- tempted 写 > ~100 行才测试时

**何时不用**：单文件单函数、范围已极小的变更。

## 切片策略

- **垂直切片优先**：一条完整端到端路径
- **契约优先**：先定 API contract 再前后端并行
- **风险优先**：先做最不确定的

## 实现规则

- **Rule 0 简单优先**：写前问"最简单能工作的方案是什么"；三行相似代码胜过过早抽象；先写朴素正确版
- **Rule 0.5 范围纪律**：只动任务所需；发现的问题记下不修（"NOTICED BUT NOT TOUCHING"）
- **Rule 1** 一次只改一件事
- **Rule 2** 每片后保持可编译可测试
- **Rule 3** 未完成功能用 feature flag
- **Rule 4** 安全默认（默认关、opt-in）
- **Rule 5** 每片可独立 revert（删除与替换分两提交）
- 用仓库自身命令验证（npm test / ./gradlew test / pytest 等）
- 成功运行后不重复同一命令（除非代码又改了）

## 红旗

- 写 >100 行未跑测试
- 单增量含多个无关变更
- "顺手也加一下"扩范围
- 跳测试/验证图快
- 片间构建/测试破损
- 大量未提交变更累积
- 第三个用例前就建抽象
- 动任务范围外文件
- 无代码变更下重复跑同一 build/test

## 验证

- [ ] 每片单独测试并提交
- [ ] 全套测试通过；构建干净
- [ ] 端到端按 spec 工作
- [ ] 无未提交残留
